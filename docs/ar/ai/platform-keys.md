# حل مفاتيح المنصة

يوفر حل مفاتيح المنصة إدارة مركزية لمفاتيح API للذكاء الاصطناعي لجميع عمليات الطبقة المُدارة. بدلاً من تخزين المفاتيح في متغيرات البيئة، يقوم المسؤولون بتهيئة وتدوير المفاتيح من خلال لوحة الإدارة.

## تدفق الحل

```
طلب المستخدم
  -> التحقق من إعداد الذكاء الاصطناعي الخاص بالمستخدم (getUserAIModel)
  -> إذا لم يكن هناك إعداد للمستخدم + طبقة managed_payg
       -> حل مفتاح المنصة (getPlatformAIModel)
            -> قراءة المزوّد الافتراضي من billing_config
            -> فك تشفير المفتاح من platform_ai_config
            -> إذا لم يكن للمزوّد الافتراضي مفتاح نشط
                 -> تكرار ai_fallback_order
                 -> إرجاع أول مزوّد بمفتاح نشط
            -> إذا لم يكن لأي مزوّد مفاتيح
                 -> رمي errors:ai.noPlatformKey
```

## الدوال الرئيسية

| الدالة | الغرض |
|--------|-------|
| `getPlatformAIModel()` | إرجاع نموذج الذكاء الاصطناعي الافتراضي للمنصة مع سلسلة الاحتياط |
| `getPlatformAIModelForProvider(provider, model?)` | إرجاع نموذج لمزوّد محدد |
| `getPlatformAPIKey(provider)` | إرجاع مفتاح API المفكك التشفير لمزوّد |
| `getAllPlatformConfigs()` | إرجاع جميع المزوّدات النشطة مع مفاتيح مفكوكة التشفير (للاستخدام الداخلي فقط) |

## سلوك التخزين المؤقت

يتم تخزين المفاتيح المفكوكة التشفير مؤقتًا في الذاكرة لمدة **60 ثانية** لتجنب الوصول إلى قاعدة البيانات في كل طلب ذكاء اصطناعي.

- التخزين المؤقت هو مثيل عام وحيد (`platformKeyCache`)
- تنتهي صلاحية الإدخالات تلقائيًا بعد 60 ثانية
- تستدعي نقاط نهاية API الإدارية `platformKeyCache.invalidate(provider)` عند تعديل المفاتيح
- `platformKeyCache.invalidateAll()` تمسح التخزين المؤقت بالكامل

**تأخير الانتشار:** تنتشر التغييرات الإدارية على المفاتيح خلال 60 ثانية.

## سلسلة الاحتياط

يتم تهيئة سلسلة الاحتياط عبر إدخالين في `billing_config`:

1. **`default_ai_provider`** — كائن JSON `{ provider, model }` يحدد المزوّد الأساسي
2. **`ai_fallback_order`** — مصفوفة JSON لمعرّفات المزوّدات بترتيب الأولوية

### دعم المفتاح الاحتياطي

لكل مزوّد **مفتاح أساسي** و**مفتاح احتياطي**:

- يتم تجربة المفتاح الأساسي (`api_key_encrypted`) أولاً
- إذا كان الأساسي فارغًا ولكن الاحتياطي موجود (`fallback_key_encrypted`)، يتم استخدام الاحتياطي
- هذا يتعامل مع تدوير المفاتيح

## الأمان

- جميع مفاتيح API **مشفرة في حالة السكون** باستخدام AES-256-GCM
- يتم فك التشفير **فقط في الذاكرة** عند الحاجة لاستدعاءات API
- `getAllPlatformConfigs()` مقيدة بنقاط النهاية الداخلية — لا تُعرض للعامة أبدًا
- المفاتيح المقنّعة (بتنسيق `sk-*****XXXX`) تُستخدم في جميع الردود الإدارية

## تكامل الطبقة المُدارة

تتعامل دالة `getUserAIModel()` مع الاحتياط القائم على الطبقة:

1. إذا كان للمستخدم إعداد ذكاء اصطناعي خاص، يتم استخدامه (جميع الطبقات)
2. إذا لم يكن هناك إعداد وكانت مساحة العمل على طبقة `managed_payg`، يتم الاحتياط إلى `getPlatformAIModel()`
3. إذا لم يكن هناك إعداد وكانت مساحة العمل على طبقة `byo_keys`، يتم إرجاع null
