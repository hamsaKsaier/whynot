# Rewrite `frontend/` dashboard + overview widgets in Shadcn

## Agent
`design-ui-designer` (lead) + `design-ux-researcher` (layout hierarchy review) + skill `whynot-dashboard`

## Depends on
`10-validate-frontend-shell-and-auth.md`

## Goal
Rewrite the main dashboard page and its supporting overview widgets using Shadcn primitives, preserving all current data bindings and behaviour. The dashboard is the user's landing-post-login destination; it must feel fast, render empty/loading/error states cleanly, and work identically in light/dark/mobile/RTL.

## Reference
- `ARCHITECTURE.md` sections 7, 11 (usage tracking preview).
- Current dashboard code: `frontend/src/pages/DashboardPage.tsx` and any widgets in `frontend/src/components/dashboard/` or similar.
- Shadcn primitives: `card`, `tabs`, `chart` (Recharts wrapper — add if not yet present), `skeleton`, `badge`, `progress`, `tooltip`, `scroll-area`.

## Task

### 1. Inventory the current dashboard
`ls frontend/src/pages/DashboardPage.tsx frontend/src/components/dashboard/ 2>/dev/null`. Read each file. Catalog every data query, every widget, every user interaction. Do NOT change the data layer in this prompt; only the presentation layer.

### 2. Add Shadcn `chart` and supporting primitives
```bash
docker compose run --rm frontend bash -c 'bunx shadcn@latest add chart'
```
If `chart` isn't available yet, install `recharts` and write a thin `<Chart>` wrapper under `src/components/ui/chart.tsx` that matches Shadcn's token-based theming.

### 3. Compose the new `DashboardPage`
Structure:
- **Hero strip** — greeting with user name, quick-action buttons (Create Project, Run Test, Invite Team).
- **KPI grid** — 4 cards: Active Projects, Tests Run (last 7d), Passing Rate, Credits Remaining (if on PAYG tier). Each KPI card has: icon (Lucide), label, big number, delta badge (↑/↓ vs previous period), tiny sparkline.
- **Tabs** — "Activity", "Recent Runs", "Errors", "Usage".
  - Activity: list of recent events (test runs, agent sessions, flag changes, etc.) with timestamps.
  - Recent Runs: compact table of last 20 executions with status badges, linked to a detail route.
  - Errors: stack-trace snippets for recent failures.
  - Usage: line + bar charts for the last 30 days (API calls, AI tokens, credits used).
- **Empty states**: for each tab, a Shadcn `Card` with an icon, a helpful message, and a CTA link.
- **Loading states**: `Skeleton` cards that match the final layout's dimensions.
- **Error states**: `Alert` with retry button.

### 4. KPI + widget components
Create each as a small, testable, single-file component:
- `frontend/src/components/dashboard/KpiCard.tsx`
- `frontend/src/components/dashboard/Sparkline.tsx`
- `frontend/src/components/dashboard/ActivityFeed.tsx`
- `frontend/src/components/dashboard/RecentRunsTable.tsx`
- `frontend/src/components/dashboard/ErrorsPanel.tsx`
- `frontend/src/components/dashboard/UsageCharts.tsx`
- `frontend/src/components/dashboard/DashboardHero.tsx`

Each component receives typed props, no data-fetching inside (the page wires the queries). This keeps tests simple.

### 5. Wire data

If a widget needs data that the gateway doesn't yet expose (Credits remaining, usage charts), stub with a clearly-labelled TODO and open a note for prompt 57 (usage-events backbone). The widget must still render the empty/loading state correctly.
